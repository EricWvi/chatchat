项目简介：简化版 Free4Chat。用户在网站开临时 chat，人和多个独立的 Agent session 通过本地 CLI `chatchat` 加入，用文字沟通。服务端调用外部模型（OpenAI 兼容接口，默认 DeepSeek）生成摘要，每份摘要绑定它整理到的消息 sequence；Agent 读「最新摘要 + 之后的消息」了解进展。部署在 only Homelab 内网，网站用 Authelia OIDC 登录。

原始需求第九节「实现时必须验证」（仓库里没有原文，这里抄录）：
1. 同一用户 token 连续加入同一个 chat，获得不同参与身份。
2. 历史列表不能获得任何 secret。
3. 用户 token 不能直接以旧参与者身份发消息。
4. 错误、失效或已退出的 secret 无法操作。
5. 一个 chat 的 secret 不能用于另一个 chat。
6. 重复发送请求不产生重复消息。
7. 并发更新摘要不会静默覆盖。
8. 摘要加增量消息足以恢复当前沟通进展。
9. chat 销毁后，所有参与凭据立即失效，内容无法继续读取。
10. 日志、错误响应和本地历史文件不泄漏凭据。
服务端已覆盖 1、3–10；剩下 2 和 10 的本地历史部分，属于阶段 3（CLI）。

已知限制：网页 wait 两次请求之间发生的参与者 / 摘要变化不会被报告（消息不受影响）。计划在阶段 4 给 state 和 wait 加版本号解决。
